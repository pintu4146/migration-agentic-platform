1 · Application Bootstrap & Lifespan

main.py FastAPI replaced the old on_event("startup") hooks with a single lifespan context manager — everything before yield is startup, everything after is shutdown.

What this project does

@asynccontextmanager
async def lifespan(app: FastAPI) -> AsyncGenerator[None, None]:
    # ── STARTUP ──────────────────────────────────────────
    setup_langsmith()                     # tracing
    provider_factory = ProviderFactory()
    await provider_factory.initialize()   # MUST be awaited (singleton)
    await provider_factory.primary_provider.health_check()

    yield                                 # app is alive here

    # ── SHUTDOWN ─────────────────────────────────────────
    provider_factory = None               # release resources

The lifespan=lifespan parameter is passed to FastAPI(). In tests you must mock or await initialize() before importing app modules because config.py validates at import time.

⚠ Gotcha — docs hidden in production

app = FastAPI(
    docs_url="/docs" if settings.environment != "production" else None,
    redoc_url="/redoc" if settings.environment != "production" else None,
)

Swagger UI is disabled in production by passing None. Classic security practice.

2 · CORS Middleware

main.py Middleware is added via app.add_middleware() — order matters; CORS must be registered early.

app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins,   # ["http://localhost:3000"]
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)

settings.cors_origins comes from .env — the Vite dev server on port 3000 is whitelisted. In production you'd tighten allow_methods and allow_headers.

How middleware execution works: FastAPI wraps every request in middleware layers (LIFO order for response). Each middleware calls await call_next(request) to pass control down. Custom middleware inherits BaseHTTPMiddleware.

3 · Exception Handlers

main.py Two global exception handlers are registered — one for Pydantic validation failures, one catch-all.

Validation Error Handler (422)

@app.exception_handler(RequestValidationError)
async def validation_exception_handler(
    request: Request,
    exc: RequestValidationError
) -> JSONResponse:
    logger.warning(f"Validation error: {exc.errors()}")
    return JSONResponse(
        status_code=422,
        content=ErrorResponse(
            error="Validation error",
            detail=str(exc.errors())
        ).model_dump()          # Pydantic v2 — not .dict()
    )

Overrides FastAPI's default 422 response so the shape matches the project's ErrorResponse schema.

General Exception Handler (500)

@app.exception_handler(Exception)
async def general_exception_handler(
    request: Request,
    exc: Exception
) -> JSONResponse:
    logger.error(f"Unhandled exception: {str(exc)}", exc_info=True)
    return JSONResponse(
        status_code=500,
        content=ErrorResponse(
            error="Internal server error",
            # hide detail in production — security best practice
            detail=str(exc) if settings.environment != "production" else None
        ).model_dump()
    )

HTTPException — raised inline in route handlers

# 400 Bad Request
raise HTTPException(status_code=400, detail="Filename is required")

# 404 Not Found
raise HTTPException(status_code=404, detail=f"Project '{id}' not found")

# 409 Conflict — with a structured detail dict
raise HTTPException(
    status_code=status.HTTP_409_CONFLICT,
    detail={"message": "Already exists", "project_id": pid, "exists": True}
)

# 503 Service Unavailable
raise HTTPException(
    status_code=status.HTTP_503_SERVICE_UNAVAILABLE,
    detail="MCP connector unavailable"
)

Key pattern: every route does except HTTPException: raise before the generic except Exception block — so intentional HTTP errors are never swallowed by the catch-all.

4 · Pydantic v2 Schemas

models/schemas.py Pydantic v2 All request/response shapes are Pydantic BaseModel classes.

PatternExample from this project

Optional fields detail: Optional[str] = Field(default=None)
Enum types class ProviderType(str, Enum): OPENAI = "openai"
Swagger examples model_config = ConfigDict(json_schema_extra={"example": {...}})
Serialisation response.model_dump() — v2 replacement for .dict()
Nested models MCPRetrievalRequest has a nested MCPRetrievalProfile field

Why str, Enum base?

Using class ProviderType(str, Enum) makes the enum JSON-serialisable directly. FastAPI serialises it as the string value, not the enum name — critical for proper OpenAPI schema generation.

5 · Dependency Injection

documents.py projects.py mcp.py Depends()

# Define a dependency function
async def get_qdrant_store() -> QdrantStore:
    store = QdrantStore()
    await store.initialize()
    return store

# Inject it into a route — FastAPI resolves automatically
@router.post("/upload", response_model=DocumentUploadResponse)
async def upload_document(
    file: UploadFile = File(...),
    project_id: str = Form("default"),
    qdrant_store: QdrantStore = Depends(get_qdrant_store)   # ← injected
):
    ...

Benefits: testable (swap the dependency in tests), reusable across routes, async-native. The Depends() function can itself depend on other dependencies — forming a graph.

Singleton pattern via global + Depends

# mcp.py
_mcp_connector: MCPConnector | None = None

async def get_mcp_connector() -> MCPConnector:
    global _mcp_connector
    if _mcp_connector is None:
        _mcp_connector = MCPConnector()
    return _mcp_connector

First call creates the instance; subsequent calls return the cached one. Raises 503 if creation fails — the dependency itself is responsible for error handling.

6 · APIRouter — Modular Routing

Each domain area has its own APIRouter with a common prefix and tag. They are registered in main.py.

# documents.py
router = APIRouter(prefix="/api/documents", tags=["documents"])

# orchestration.py
router = APIRouter(prefix="/api/orchestration", tags=["orchestration"])

# mcp.py
router = APIRouter(prefix="/mcp", tags=["MCP"])

# main.py — register all routers
app.include_router(mcp_router)
app.include_router(orchestration_router)
app.include_router(documents_router)
app.include_router(projects_router)

Custom responses declared on a route

@router.get(
    "/health",
    response_model=MCPHealthResponse,
    summary="Check MCP Gateway health",
    responses={
        200: {"description": "MCP Gateway is healthy"},
        503: {"description": "MCP Gateway unavailable", "model": ErrorResponse}
    }
)

The responses dict enriches the OpenAPI spec — 503 will show the ErrorResponse schema in Swagger UI.

8 · File Upload Pattern

documents.py A production-grade multi-step file upload endpoint.

@router.post("/upload", response_model=DocumentUploadResponse)
async def upload_document(
    file: UploadFile = File(...),
    project_id: str = Form("default"),
    qdrant_store: QdrantStore = Depends(get_qdrant_store)
):
    # 1. Validate filename & extension
    if not ParserFactory.is_supported(file.filename):
        raise HTTPException(400, detail="Unsupported file type")

    # 2. Write to a temp file (avoid holding bytes in memory)
    with tempfile.NamedTemporaryFile(delete=False, suffix=ext) as tmp:
        content = await file.read()
        tmp.write(content)
        temp_path = tmp.name

    try:
        parsed = ParserFactory.parse_file(temp_path)
        chunks  = chunker.chunk_document(parsed)
        embedded = await embedder.embed_chunks(chunks)
        await qdrant_store.add_documents(embedded, collection_name)
    finally:
        os.unlink(temp_path)    # always clean up, even on error

Lessons: Always use try/finally to delete temp files. Validate before processing. Re-raise HTTPException before the generic handler.

9 · Server-Sent Events (SSE) Streaming

orchestration.py StreamingResponse Real-time workflow state pushed to the browser without WebSockets.

@router.get("/stream/{project_id}")
async def stream_workflow_state(project_id: str):
    async def event_generator():
        # SSE format: event name + data line
        yield f"event: state_update\n"
        yield f"data: {json.dumps(payload)}\n\n"   # double newline = end of event

        while True:
            await asyncio.sleep(0.5)               # poll Redis
            updated_state = await state_manager.get_state(project_id)

            if phase_changed:
                yield f"event: phase_transition\n"
                yield f"data: {json.dumps(phase_event)}\n\n"

    return StreamingResponse(
        event_generator(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "Connection": "keep-alive",
            "X-Accel-Buffering": "no"   # disable nginx proxy buffering
        }
    )

Named events vs generic message

This project uses named events (state_update, phase_transition, error). The frontend must use eventSource.addEventListener('state_update', ...) — NOT eventSource.onmessage, which only fires for unnamed events.

10 · Configuration with Pydantic Settings

config.py BaseSettings Environment variables are loaded and typed automatically.

class Settings(BaseSettings):
    model_config = SettingsConfigDict(
        env_file=".env",
        case_sensitive=False,
        extra="ignore"          # silently ignore unknown env vars
    )
    openai_api_key: Optional[str] = Field(default=None)
    environment: str = Field(default="development")
    cors_origins: list[str] = Field(default=["http://localhost:3000"])

    @property
    def default_provider(self) -> str:
        if self.openai_api_key: return self.primary_provider
        elif self.gemini_api_key: return "gemini"
        else: raise ValueError("No LLM provider configured")

settings = Settings()          # module-level singleton
settings.validate_providers()  # validates at import time

⚠ Import-time validation

Because settings.validate_providers() runs at import, tests must set os.environ variables before any from app.X import ... statement. The project does this in backend/tests/conftest.py.

11 · Structured Logging

logging_config.py A custom JSONFormatter emits structured logs that are easy to ingest into observability platforms.

class JSONFormatter(logging.Formatter):
    def format(self, record: logging.LogRecord) -> str:
        return json.dumps({
            "timestamp": datetime.utcnow().isoformat(),
            "level": record.levelname,
            "logger": record.name,
            "message": record.getMessage(),
            "module": record.module,
            "function": record.funcName,
            "line": record.lineno,
            **({"exception": self.formatException(record.exc_info)}
               if record.exc_info else {})
        })

Every module uses logger = logging.getLogger(__name__) — giving per-module log namespaces that can be tuned individually (e.g., httpx set to WARNING to suppress noise).

12 · Interview Questions & Answers

All answers are grounded in this project's patterns.

Q1. What is the difference between @app.on_event("startup") and the lifespan context manager?

on_event is deprecated. The lifespan context manager (introduced in FastAPI 0.93) handles both startup and shutdown in a single async with block using yield. It's more predictable for resource cleanup and plays well with async context managers. This project uses it in main.py to initialise ProviderFactory and close it on shutdown.

Q2. How does Depends() work and what are its advantages?

FastAPI calls the dependency function and injects its return value into the route. Dependencies are cached per request by default (not per app). They can be async, can raise HTTPException, and can be nested. This project uses Depends(get_qdrant_store) on every document/project route — enabling easy test-time mocking and preventing repeated initialisation code.

Q3. How do you handle validation errors differently from general exceptions in FastAPI?

Register two separate @app.exception_handler decorators: one for RequestValidationError (422 — Pydantic failures) and one for Exception (500 — unexpected crashes). The project always re-raises HTTPException before the catch-all, so intentional HTTP errors are never accidentally converted to 500s.

Q4. What is StreamingResponse and when would you use it?

StreamingResponse wraps an async generator and streams data to the client incrementally without buffering the full response. Used here for Server-Sent Events at GET /api/orchestration/stream/{project_id} — it pushes real-time workflow state to the React frontend. Set media_type="text/event-stream" and include Cache-Control: no-cache headers.

Q5. Why use APIRouter instead of putting all routes on app?

APIRouter lets you group related routes into separate files with a shared prefix, tags, and dependencies. You register them all in main.py via app.include_router(). This project has four routers: mcp, orchestration, documents, projects — each in its own file, keeping main.py clean.

Q6. How does FastAPI differ from Flask for async code?

FastAPI is built on Starlette and is natively async — you write async def route handlers that run on uvicorn's event loop. Flask requires extensions (aioflask/Quart) to achieve the same. FastAPI also has first-class Pydantic integration (automatic schema validation + OpenAPI docs), whereas Flask needs Flask-Marshmallow or similar.

Q7. What does response_model do and what are its performance implications?

response_model tells FastAPI to serialise and validate the return value against the specified Pydantic model before sending the response. It strips extra fields, converts types, and generates the OpenAPI response schema. The slight overhead is worth it for correctness. You can add response_model_exclude_none=True to omit None fields from the JSON response.

Q8. How do you handle file uploads in FastAPI?

Use UploadFile = File(...) combined with form fields via Form(). Call await file.read() to get bytes. Best practice (shown in this project): write to a tempfile.NamedTemporaryFile, process it, then delete in a finally block to avoid leaked temp files.

Q9. How do you configure CORS in FastAPI and what does allow_credentials mean?

Add CORSMiddleware via app.add_middleware(). allow_credentials=True enables cookies/auth headers in cross-origin requests — this requires allow_origins to be an explicit list (not ["*"]). This project whitelists localhost:3000 (Vite dev server) and localhost:8000.

Q10. How does Pydantic v2 differ from v1 in a FastAPI context?

Key differences: .model_dump() replaces .dict(); model_config = ConfigDict(...) replaces inner class Config; json_schema_extra replaces schema_extra; validators use @field_validator and @model_validator. Pydantic v2 is also significantly faster due to a Rust core. FastAPI ≥ 0.100 fully supports Pydantic v2.

Q11. What is BackgroundTasks and where would you use it?

BackgroundTasks lets you schedule work to run after the response is sent. For example, after uploading a document you might return 200 immediately and process embeddings in the background. This project does processing synchronously in the upload handler — a BackgroundTasks refactor would improve perceived latency for large files.

Q12. How do you prevent sensitive data leaking in error responses?

Check the environment before including detail strings: detail=str(exc) if settings.environment != "production" else None (used in general_exception_handler). In production, log the full traceback server-side and return only a generic message to the client.

Q13. What is the purpose of status from fastapi and when do you use it vs raw integers?

from fastapi import status gives named constants like status.HTTP_409_CONFLICT. These are preferred over magic numbers for readability and typo-safety. This project uses both — raw integers for simple cases (status_code=400) and the constants for less-common codes (status.HTTP_503_SERVICE_UNAVAILABLE).

Q14. How does pydantic_settings.BaseSettings work?

BaseSettings reads field values from environment variables (matching by name, case-insensitive by default). A .env file is loaded via env_file=".env". Priority: explicit env vars override .env which overrides model defaults. extra="ignore" silently discards unknown vars, preventing crashes when deploying with extra env vars.
